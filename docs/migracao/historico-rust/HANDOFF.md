## Onde está cada coisa
- **Branch `main`:** mockup estático (HTML/CSS/JS) e documentação neutra de stack.
- **Branch `stack/rust-topcoat`:** implementação real em `platform/` (Rust + Topcoat). Stack escolhida; reavaliar ao final de todas as implementações. Convenção: cada stack candidata em `stack/<nome>`.
- **Documentos:** `docs/FAQ-ARQUITETURA.md` (decisões, itens 1–14), `docs/PENDENCIAS.md` (roadmap e status — fonte da verdade do que falta), `platform/README.md` (como rodar), `platform/docs/SPIKE-TOPCOAT.md` (API real do Topcoat 0.9 e custo de saída), `platform/loadtest/RESULTADOS.md` (capacidade na VM de destino). ## Como rodar (branch `stack/rust-topcoat`, em `platform/`)
- Nativo: `bash scripts/demo.sh` → http://localhost:8080 (apps em 9101–9103).
- Containers: `docker compose up -d --build` (+ `scripts/sample-packages.sh` após rebuild da imagem dos apps); `docker compose down`.
- App isolado: `bash scripts/dev-app.sh ativos` (sem Docker/plataforma/admin; limites via Job Object no Windows).
- Testes: `cargo fmt --all --check && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace && node --test js-tests/`; com Postgres (container descartável `hub-testdb`, ex.: `docker run -d --name hub-testdb -e POSTGRES_PASSWORD=testpw -p 127.0.0.1:55499:5432 postgres:16-alpine`; remova depois): `HUB_DB_TEST_URL=postgres://postgres:testpw@127.0.0.1:55499/postgres cargo test -p hub-sdk --test db -- --ignored --test-threads=1`, `… -p hub-demo-apps --test db …` e `… -p hub-ops --lib -- --ignored --test-threads=1` (provisionamento + troca atômica do banco na restauração); com Docker: `DOCKER_AVAILABLE=1 cargo test -p hub-runtime --test docker -- --ignored` (blue/green real, varredura de tarefas órfãs e montagem só de subdiretórios do volume nas tarefas).
- Sem indisponibilidade (compose no ar): `node loadtest/zero-downtime.mjs --rps 200` (3 deploys de produção + rollback + staging do `ativos` sob carga; cria `hub-zd-oha-*`).
- DR, OOM e staging (compose no ar): `node loadtest/dr.mjs` (com snapshot de segurança, manutenção e credenciais fora do env), `node loadtest/e2e/w5-oom.mjs` (limite pelo caminho da UI; redeploy com o app degradado → alerta de recuperação), `node loadtest/e2e/w5-fixes-staging.mjs` (link repassado e logout); JS: `node --test js-tests/`.
