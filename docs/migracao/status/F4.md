# F4 - API publica /api/v1, MCP e OAuth 2.1

Codigo em `platform-py/hub/api/`: `ops.py` (tabela de operacoes + gerador OpenAPI), `schemas.py` (modelos pydantic = componentes `utoipa`; exemplos em `examples.json`), `v1.py` (rotas `/api/v1`, autorizacao, fachada em processo, paginacao, taxa, auditoria), `mcp.py` + `mcp_apps.py` (MCP e ferramentas dos apps), `oauth.py` (servidor de autorizacao + recurso), `cors.py`, `records.py` (estado com validade), `config.py` (`[api]`, `[mcp]`, `[mcp.oauth]` + `HUB_*`). Template `oauth_page.html` (casca das paginas avulsas). Medida em `app.py`: middleware aceita bearer `hubo_` (so no `/mcp`), `hubt_` nas superficies do escopo, 401 com `WWW-Authenticate`; gateway nao exige CSRF para token (sem navegador); token restrito a apps vale so nos seus apps.

- **Tabela unica** `OPS` (39 operacoes em 37 caminhos): gera rotas `/api/v1/*`, `openapi.json` (`/api/v1/openapi.json`, `/api/docs`) e ferramentas MCP. Fachada: cada operacao chama a rota interna (`/api/ops|admin|me`) **em processo** (ASGI, escopo `hub_facade` com a identidade do chamador; sem rede, sem duplicar logica). RBAC = o da rota interna (`api_required`), escopos `api:read|api:write|secrets:reveal`, escopo de apps do token resolvido dos ids (404 se o id nao existe), cota por dono (token + sessao dividem), erros RFC 9457, auditoria "API v1: <op>" em toda mutacao.
- **MCP** `/mcp` (`[mcp].path`): duas eras (2026-07-28 sem sessao + legado com `initialize`/`Mcp-Session-Id`, `GET` SSE, `DELETE`, lote so na 2025-03-26), JSON-RPC proprio, SSE para `tools/call` moderno, so `Authorization: Bearer` (OAuth ou pessoal com `mcp`), checagem de `Origin` (URL publica + `HUB_MCP_ALLOWED_ORIGINS`), ferramentas filtradas por RBAC, recursos `hub://apps|status`. Destrutivas: `approve_in_hub` (pedido "Aprovar acao do agente" na Inbox + reautenticacao em `/account/agent-approval/{id}`, ja da F2), `confirm`, `deny`; `confirm_token` de uso unico amarrado a usuario/ferramenta/argumentos; varredura de vencidos. **Ferramentas dos apps** `<app>.<tool>`: lista o MCP interno (`/_hub/mcp`, token interno do cofre), classifica leitura x mutacao pelo `openapi.json` do app, chama em nome do usuario (identidade assinada, `x-hub-mcp-op`), descricao/resultado rotulados como nao confiaveis.
- **OAuth 2.1**: `.well-known/oauth-protected-resource[/mcp]` e `oauth-authorization-server`, `/oauth/register` (DCR, limites por IP + global), `/oauth/authorize` (consentimento, PKCE S256 obrigatorio, `resource`, `iss`), `/oauth/token` (codigo de uso unico com replay revogando a concessao; refresh com rotacao e deteccao de reuso + aviso na Inbox), `/oauth/revoke`, clientes por documento de metadados (CIMD: so HTTPS publico, IP fixado, sem redirect, 16 KiB), bloqueio/remocao pela administracao (`POST /admin/oauth/*`), tela do usuario `/account/authorized-apps` (hooks da F2 ligados). So hashes no estado (`records`: banco de estado ou memoria). Emissor = `HUB_PUBLIC_URL` (sem ela so loopback). Token OAuth = token sintetico com dono, so no `/mcp`.
- **CORS** maquina-a-maquina (`cors.py`, middleware mais externo): preflight 204 antes de auth/origem; `Allow-Origin: *` sem credenciais; `Expose-Headers: WWW-Authenticate, Mcp-Session-Id, MCP-Protocol-Version`; `/oauth/authorize` fora. `HUB_MCP_PUBLIC_NETWORK` libera `/mcp`, `/.well-known/*`, `/oauth/*` do CIDR do plano de controle; `HUB_LOG_MCP_REQUESTS=1` registra os pedidos.

## Lacunas
- **Pagina `/admin/tokens`** (Acesso > Tokens de API, com a secao OAuth de clientes/concessoes) nao existe no hub Python (nao estava na F3); as acoes `POST /admin/oauth/{revoke-grant,block-client,unblock-client,remove-client}` e `/account/authorized-apps` existem e estao testadas, mas a tela de admin que as chama nao.
- Ferramentas dos apps: **ao vivo no `:8090` aparecem 0** porque o token interno guardado no cofre do `hubpy-web` ja nao confere com o dos containers `hubpy-app-*` (401 `token interno invalido` em todos os 5 apps; pendencia de ambiente anterior a F4, nao tocada); a funcionalidade esta coberta por teste com upstream ASGI. O hub classifica pelo `openapi.json` **do app no ar** (a pipeline Python valida mas nao guarda o openapi do pacote ativo; volta com o blue/green da F5). Sem documento, nenhuma ferramenta e leitura (tudo pede aprovacao).
- Varredura de `confirm_token`/pedidos vencidos e preguicosa (a cada chamada ao `/mcp`, no maximo a cada 30 s), nao uma tarefa periodica; nao ha varredura na partida (o Python guarda os pedidos em `inbox.json`).
- `stdio` em `[mcp].transports` so e validado (a ponte `hub mcp` e a CLI Python, fora desta tarefa). `jobs` em `apps_get` devolve nomes (como o Rust) embora o esquema diga objetos: defeito herdado, mantido por equivalencia.
- Tela de consentimento so em pt-BR (como no Rust). ui-sweep nao rodado (so paridade DOM/pixels das duas paginas e testes).
